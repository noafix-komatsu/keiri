## 受取利息の源泉分

入金額は源泉税 15.315% 控除後。過去仕訳（3〜5 月）の方式に合わせ、1 つの仕訳に 2 行で登録する。

```
借方 普通預金/GMOあおぞら  入金額     / 貸方 受取利息  総額      摘要: 普通預金 利息
借方 法人税等              源泉分     / （貸方なし）                摘要: 普通預金 利息　源泉分
```

- 総額 = 入金額 ÷ 0.84685 を整数に丸め、源泉分 = 総額 − 入金額 で検算する（源泉分 ≒ 総額 × 15.315% 切り捨て）。
- 例: 559 → 660/101、497 → 586/89、730 → 862/132、300 → 354/54。

## 役員社宅（2026-07 開始、三井不動産レジデンシャルリース、賃料 210,000/月）

会社が借主、代表が居住。税理士との合意で **賃料の 50% を代表負担** とする。契約期間 2 年（更新料あり）。

- 初期費用（2026-06-19、630,000）: 敷金 210,000 / 長期前払費用（礼金）210,000 / 地代家賃（7 月分）210,000 — 普通預金 630,000。礼金・敷金は会社全額負担。
- 礼金 210,000 は 20 万円以上のため繰延資産。償却期間は契約期間の 2 年（24 か月）。2026 年度の償却額は 6 か月分 52,500 円。**償却仕訳は決算時に税理士が入れる。**
- 敷金は全額返還前提。契約書に敷引・償却条項が見つかれば、その分を長期前払費用に振り替える。
- 家賃徴収はクレディセゾン（家賃保証）経由。初年度保証料 105,000 は 20 万円未満の短期前払費用として支払手数料で一括費用計上。
- 毎月の賃料明細（210,000）→ 地代家賃 210,000 で全額計上し、**同日付で別仕訳「未収入金 105,000 / 雑収入 105,000」**（摘要: 役員社宅使用料 ○月分（代表負担 賃料210,000の50%））を作成する。
- 代表は月ごとに 105,000 を会社口座へ振り込む（摘要「社宅使用料 ○月分」）。入金明細は「普通預金 / 未収入金」で消し込む。
- 2026-09-10 に 7 月分・8 月分の 105,000 × 2 が入金され消込済み（仕訳番号 91・92）。未収入金残高 0。9 月分以降は賃料の口座引落のたびに 105,000 を計上し、代表の振込で消し込む。

## TCG カード売却（トレカバンク）

- 代表が個人で購入したオリパ（5,000 円、領収書なし）で当たったカードを会社に無償で引き渡し、会社名義で売却。会社側は **売上高で全額計上し原価は計上しない**（受贈益と原価が同額で相殺されるため結果は同じ。5,000 円は証憑がなく僅少なので計上しない）。
- 自社所有物の売却なので古物商許可は不要。
- **代表個人側に所得税法 59 条のみなし譲渡課税（1 点 30 万円超の収集品）の論点がある。** 税理士に「個人が当てたカードを法人へ無償で引き渡して法人名義で 1,101,000 円で売却した。みなし譲渡課税の扱いと代表個人の確定申告への影響」を確認する。

## 登録手順（MCP `mfc_ca`）

1. `getTransactions` を `journalizing_statuses: ["none"]` で取得（期間は会計期間内、366 日以内）。
2. `getJournals` で過去仕訳を確認し、上表に当てはめる。
3. 提案リストをユーザーに提示し、承認を得る。**承認前に登録しない。** 確信のない明細は保留。
4. `postTransactionJournalize` で 1 行仕訳を作成（`transaction_id` と `account_id` のみ。`tax_id` は指定しない）。
5. 受取利息や役員社宅の初期費用のように複数行が必要なものは、4 の戻り値の `journal.id` に対して `putJournals` で branches を 2 行に書き換える（明細との紐付けは維持される）。
6. 明細に紐付かない仕訳（社宅使用料の未収入金など）は `postJournals` で作成する（memo に自動で「Claude Code (mfc_ca)」が入る）。
7. 再度 `getTransactions` で未仕訳が保留分だけになったことを確認する。

## API の注意点

- MCP には連携サービスの再取得を実行するツールがない。銀行の新しい明細を即時反映したいときは MF 画面の「データ連携 → 登録済一覧 → 一括再取得」をユーザーに依頼する。

- **ID は API が返した URL エンコード済み文字列（`%2B` `%2F` `%3D`）をそのまま渡す。** `+` `/` にデコードすると `invalid_request_body_value` になる。
- `postTransactionJournalize` は勘定科目の既定税区分を `tax_id` に入れることがあるが、税区分名は空で実害なし。`putJournals` で書き換えると null になる。
- `getJournals` の結果は 1 ページで 80KB を超えることがある。ツール結果ファイルを Python で読んで集計する。
- 明細の `content` に `�` が含まれることがある（店名の文字化け）。金額と日付の周期で判定する。
